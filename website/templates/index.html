What it is

A control plane for the MCP servers your company runs.

MCP Runtime is a self-hosted Kubernetes control plane for internal MCP servers. It deploys and routes those servers, authorizes tool calls, expires or revokes access, and audits requests inside your cluster, next to the data and services the servers already use.

You decide who can call a tool such as delete_invoice, up to what trust level, and for how long. Servers, grants, and sessions are Kubernetes resources, and a gateway in each server pod enforces them on every call.

01 / Definition

One manifest becomes a governed MCP endpoint.

mcpserver.yaml mcpruntime.org/v1alpha1 
apiVersion: mcpruntime.org/v1alpha1
kind: MCPServer
metadata:
  name: payments
spec:
  image: registry.example.com/payments-mcp:v1.0.0
  port: 8088
  publicPathPrefix: payments
  gateway:
    enabled: true
  analytics:
    enabled: true

Deploy an MCP server the way you deploy any other service.

  • Define the server, image, port, route, gateway, and analytics in one resource.
  • Let the operator reconcile services, ingress, rollouts, and updates.
  • Configure policy, audit, and analytics on the same resource.
02 / Architecture

Three components.

A

Manager

A Kubernetes-native control plane to install the stack, reconcile MCPServer resources, and keep deployments healthy.

B

Registry

Image and deployment workflows for publishing MCP servers into environments your platform team controls.

C

Broker

A governed gateway that brokers agent access, applies policy before tool calls run, and records what happened.

03 / Capabilities

What it does.

Deploy servers, apply access policy, route requests through the gateway, and inspect audit and traffic data from one place.

Managed deployments

Define MCP servers once as Kubernetes CRDs. The operator handles services, rollouts, routes, and updates in a GitOps-friendly workflow.

Company access model

Grants and sessions make consent, trust level, expiry, and revocation Kubernetes resources. A call is denied unless a grant and a session allow it.

Hosted platform shape

platform.mcpruntime.org shows the platform UI as it looks after installation. Anyone can browse the preview catalog; signed-in users can publish servers to it.

Brokered tool calls

Agent traffic goes through a gateway that checks policy before a tool runs.

Operational visibility

See each MCP call with its policy decision, timing, tool name, and status in dashboards and the analytics API.

Audit-ready history

Every governed request is recorded for security review, incident response, and compliance workflows.

Platform stack included

The control plane runs in mcp-platform. Audit and telemetry run in mcp-observability. MCP servers stay in their own namespaces. Registry, ingress, API, UI, Grafana, and Prometheus install with setup.

04 / Runbook

Install the stack, then connect servers.

  1. Build go build -o bin/mcp-runtime ./cmd/mcp-runtime
  2. Bootstrap ./bin/mcp-runtime bootstrap
  3. Install ./bin/mcp-runtime setup --test-mode
  4. Verify ./bin/mcp-runtime status
